# CLAUDE.md

Голосовая викторина по Minecraft на русском языке. Задеплоена на GitHub Pages:
https://eternited.github.io/minecraft-quiz/

## Архитектура

- **Всё приложение — один файл `index.html`**: React 18 (UMD с unpkg CDN) + Babel standalone,
  JSX транспилируется прямо в браузере. Сборки, package.json и зависимостей у приложения нет.
- `tests/` — юнит- и e2e-тесты (см. ниже), на рантайм приложения не влияют.
- Стили — JS-объекты (inline styles) внутри index.html, пиксельная Minecraft-эстетика.
- Экраны — конечный автомат на `useState("screen")`:
  `start` → `playing` → `evaluating` → `result` → (цикл до 10 вопросов) → `final`.
- **Навигация на главную** (`goHome`/`armExit`): из `playing` — кнопка 🏠 в топбаре,
  из `result` — «НА ГЛАВНУЮ»; обе с двухтаповым подтверждением («Выйти?»,
  сброс взвода через 3 с — защита от случайного тапа, прогресс игры теряется).
  С `final` — «НА ГЛАВНУЮ» без подтверждения. `goHome` инкрементирует `gameIdRef`
  и сбрасывает префетч, чтобы зависшие запросы старой игры не «выстрелили» позже.
- Асинхронный игровой цикл: **префетч** — пока игрок думает над вопросом N, вопрос N+1
  уже генерируется (`prefetchRef`); история заданных вопросов и очередь тем живут
  в ref'ах (не в state), чтобы не ловить stale closures; `gameIdRef` защищает
  от гонок между старой и новой игрой («Играть снова»).
- **Версионирование**: константа `APP_VERSION` в index.html в формате
  **`"ГГГГ-ММ-ДД.N"`** (дата выкладки + номер выкладки за день), бейдж внизу
  **по центру** на всех экранах (по нему видно, доехал ли деплой/автообновление
  до устройства). **Правило: при каждом пуше, меняющем код приложения,
  обновлять APP_VERSION, беря дату командой `date +%F` НЕПОСРЕДСТВЕННО перед
  коммитом** (не по памяти — длинные сессии врут); версию упоминать в DEVLOG.
  До 2026-07-18 использовался semver (v1.0.0…v1.7.0) — история в DEVLOG.
  Бейдж — **обычный элемент в конце флекс-колонки, НЕ position:fixed**
  (fixed-вариант перекрывался кнопками, прижатыми к низу). CSS-класс
  `.version-tag` в `<style>` — единственный стиль не в JS-объектах: нужен
  каскадный фолбэк `padding-bottom` → `calc(8px + env(safe-area-inset-bottom))`
  для iPhone с «чёлкой» (viewport-fit=cover включён в мете).

## AI-интеграция (DeepSeek)

- Endpoint: `https://api.deepseek.com/chat/completions`, модель `deepseek-chat`,
  OpenAI-совместимый формат (system+user messages, `Authorization: Bearer <key>`).
- Функция `callAI(apiKey, system, user, {temperature, timeoutMs, json})`
  (бывшая `callClaude`): таймаут 15 с через AbortController,
  `response_format: json_object` (кроме проверочного вызова при сохранении ключа).
- **Температуры**: генерация вопросов 0.7 (`GEN_TEMPERATURE`),
  оценка ответов 0.2 (`EVAL_TEMPERATURE`).
- `parseJSON()` срезает markdown-фенсы и, если parse не удался, вырезает
  подстроку от первой `{` до последней `}`.
- **API-ключ** вводится на стартовом экране, проверяется тестовым вызовом при сохранении,
  хранится в `localStorage` (`mc_quiz_api_key`). Без ключа запросы к API вообще
  не делаются — сразу fallback.

## Генерация вопросов

- **Системный промпт** (`QUESTION_SYSTEM_PROMPT`): роль «составитель вопросов для
  викторины по Minecraft (Java Edition)»; только реальные, проверяемые по Minecraft Wiki
  факты; короткий однозначный ответ; **только актуальная локализация последней версии
  с анти-примерами** (стол зачарований, НЕ «чародейский стол»; незерак, НЕ «адский
  камень»); **правило многосоставных рецептов** — если верных ответов несколько,
  переформулировать до однозначности или перечислить каждый в acceptable_answers;
  инструкция самопроверки («…один общепризнанный ответ»);
  **6 few-shot примеров** (`QUESTION_EXAMPLES`) разных сложностей.
- **Формат ответа**: `{"question","correct_answer","acceptable_answers":[2–4 варианта],
  "difficulty":"easy|medium|hard"}` — `acceptable_answers` это синонимы
  и разговорные названия, их учитывают и судья, и локальный скоринг.
- **Ротация тем**: 12 тем (`TOPICS`: крафт и рецепты, мобы и их поведение, редстоун,
  зельеварение, зачарования, биомы и структуры, Нижний мир, Край, еда и фермерство,
  инструменты и броня, деревни и жители, игровые механики). `createTopicQueue`
  выбирает случайно **без повторов до исчерпания всех**, затем новый цикл;
  тема подставляется в user-промпт.
- **Сложность**: селектор на стартовом экране (смешанная/легко/средне/сложно)
  прокидывается в промпт и в фильтр fallback-банка.
- В user-промпт передаётся список уже заданных вопросов (запрет повторов).
- **Факт-чек**: каждый сгенерированный вопрос до показа проверяется вторым
  AI-вызовом (`VERIFY_SYSTEM_PROMPT`, `VERIFY_TEMPERATURE = 0`):
  `ok` — оставить (acceptable_answers дополняются вариантами проверяющего),
  `fix` — заменить неверный correct_answer (старый в допустимые НЕ переносится)
  и/или переписать формулировку через `corrected_question` (устаревшие названия
  локализации), `reject` — одна перегенерация с причиной отказа, затем
  fallback-банк. Проверяющий обязан: следить за актуальной локализацией
  и при нескольких равноправных верных ответах (ингредиенты рецепта)
  перечислить каждый в acceptable_answers. Сбой самой проверки игру
  не блокирует (вопрос идёт как есть). Мотивация: модель путала измерения
  («коренной блок острова в Крае» → «адский камень») и использовала
  устаревшие названия («чародейский стол»); латентность скрыта префетчем.

## Оценка ответов

- Судья (`EVAL_SYSTEM_PROMPT` + `buildEvalUserPrompt`) получает вопрос, правильный
  ответ, **acceptable_answers** и ответ игрока; синонимы и разговорные формулировки
  должен засчитывать на 5. **Расхождения только в окончаниях/роде/падеже/ё —
  это полное совпадение (5)**: ASR их постоянно путает («Шелковая касание»),
  правило прописано и в системном промпте, и в шкале user-промпта.
  Если эталонный ответ противоречит вопросу/фактам игры, а игрок фактически
  прав — судья обязан поставить 5 и вернуть настоящий ответ в correct_answer.
  Если вопрос допускает несколько равноправных верных ответов (любой ингредиент
  рецепта) — любой из них оценивается на 5.
  Возвращает `{"score":1..5,"comment","correct_answer"}`; score клампится в 1..5.
- **Локальный скоринг** `localScore()` — не только fallback, но и «страховка»:
  **итоговая оценка = `mergeEvaluations(судья, localScore)` — лучшая из двух**.
  Если AI занизил (кейс: эталон «Адский камень», ответ «незерак» → судья ставил 1),
  а локальная проверка видит совпадение — берётся локальная. Это гарантия кода,
  не промпта.
- Механика `localScore()`: нормализация (нижний регистр, ё→е, пунктуация→пробел),
  сравнение со **всеми** эталонами (correct_answer + acceptable_answers +
  **группы `MC_SYNONYMS`** — официальное/старое/разговорное название одного объекта:
  незерак↔адский камень, камень Края↔эндерняк, иссушитель↔визер и т.д.),
  берётся максимум. Точное совпадение = 5; **все слова эталона совпали по стемам
  и лишних значимых слов нет = тоже 5** (окончания — огрехи ASR); все слова эталона
  на месте, но есть лишние = 4; часть = 3; иначе 1. Слова сравниваются лёгким
  стеммингом (обрезка окончаний, чтобы ловить падежи), **числа — только точно**
  («10» ≠ «12»); короткие слова (≤2 букв, кроме чисел) не считаются значимыми.
  Новые пары переименований локализации добавлять в `MC_SYNONYMS`.

## Fallback без API

- При любой ошибке/таймауте генерации — встроенный банк `FALLBACK_QUESTIONS`
  (15 вопросов, у всех есть acceptable_answers), циклический индекс,
  фильтрация по выбранной сложности.
- При ошибке оценки — `localScore` (см. выше).

## Голосовой ввод и озвучка

- Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`), язык `ru-RU`,
  push-to-talk (зажать кнопку: touch + mouse события). Повторный `start()`
  обёрнут в try/catch (InvalidStateError).
- **Единый ввод**: голосовой транскрипт складывается в то же поле, что и текст
  (`textInput`), — отправляется ровно то, что игрок видит; можно поправить руками.
- Транскрипт прогоняется через `MC_CORRECTIONS` — таблицу фонетических исправлений
  Minecraft-терминов. **Важно: `\b` в JS-регулярках не работает с кириллицей**,
  границы слов построены вручную через `[^а-яёa-z0-9]` (`RAW_CORRECTIONS` +
  генератор). Не добавляй новые правила с `\b`!
- Если распознавание недоступно (Firefox и др.) — остаётся текстовое поле.
- **Озвучка вопросов**: SpeechSynthesis (`ru-RU`), автоозвучка при показе вопроса
  (переключатель на стартовом экране, `localStorage` `mc_quiz_tts`) +
  кнопка «🔊 Прочитать вопрос».

## Самообновление (PWA)

- Полный механизм и мотивация — в **`update-mechanism-guide.md`** (корень
  репозитория, перенос из «Таблицы умножения» xmulti.ru). Перед правками
  сверяться с разделом «Грабли, на которые мы уже наступили».
- **`sw.js`**: два кэша — `mcquiz-shell-v1` (оболочка; ключи `.` **и**
  `./index.html` всегда обновляются вместе — грабля №1) и `mcquiz-vendor-v1`
  (CDN-скрипты, best-effort: их сбой не роняет установку SW). HTML —
  **network-first с таймаутом 3 с** и фолбэком на кэш; HEAD не перехватывается.
- **Обнаружение новой версии**: HEAD `./index.html` c `cache:"no-store"`,
  сравнение ETag (`normalizeEtag` срезает `W/`) с копией в кэше SW. Триггеры:
  через 8 с после старта, раз в 15 минут, при возврате из фона.
- **Контексты экранов**: `playing`/`evaluating` → `hide` (не мешать вообще);
  `start` → `auto` (тихое обновление после 2,5 с покоя), но `banner`, если
  видна форма API-ключа или в ней что-то набрано (перезагрузка стёрла бы ввод);
  `result`/`final` → `banner` (плашка «Появилась новая версия · Обновить»).
- Решение принимает чистая **`updateAction()`** с защитами от циклов:
  после провала скачивания — пауза 60 с, после авто-перезагрузки
  (`localStorage.lastAutoUpd`) — 120 с.
- **`startUpdate()`**: оверлей «Обновляю приложение…» поверх всего → команда
  `refresh-shell` в SW → **перезагрузка только после подтверждения записи
  свежего HTML в кэш** (грабля №2); при сбое оверлей убирается, плашка остаётся.
- Тайминги для тестов ускоряются через `window.__MCQUIZ_TUNE__`
  (`{firstCheck, interval, calm}`), таймаут SW — `self.__MCQUIZ_SW_TUNE__.timeout`.
- **Первая доставка — вручную**: механизм приедет к пользователю после одного
  холодного перезапуска с сетью; все следующие версии — уже автоматически.

## История результатов

- Итог каждой игры пишется в `localStorage` `mc_quiz_history` (последние 20:
  дата, сумма, оценки, сложность). На стартовом экране — рекорд и последняя игра,
  на финальном — бейдж «Новый рекорд!».

## Тесты

- `cd tests && npm install && npm test` (Node 18+; браузеры не качаются —
  используется системный Chromium `/opt/pw-browsers/chromium`, переопределяется
  через `PW_CHROMIUM`).
- `unit.test.js` — чистая логика index.html (скрипт транспилируется Babel'ем
  и выполняется в Node VM с заглушками React; тестируется `window.__MCQUIZ_TEST__`).
- `e2e.test.js` — playwright-core + системный Chromium: страница поднимается
  на локальном сервере (с ETag и HEAD, как GitHub Pages; управляемые задержка
  «медленной сети», подмена index.html и ошибка 500), CDN-скрипты берутся
  из npm-пакетов (`tests/vendor/`, генерируется), DeepSeek мокается через
  route-перехват. Четыре сценария: полный цикл с API (темы, префетч,
  температуры, acceptable_answers), режим без ключа (fallback-банк, локальный
  скоринг), UX самообновления (auto/hide/banner, защита от циклов; SW
  заблокирован, кэш сеется старым ETag) и реальный Service Worker на
  harness-странице `/__harness` (оба ключа кэша, честное подтверждение
  refresh-shell на медленной сети, network-first-фолбэк по таймауту).
- `window.__MCQUIZ_TEST__` в index.html — тестовый хук с чистыми функциями,
  не удаляй при рефакторинге.

## Правила работы

- **Основная ветка — `master`**, GitHub Pages деплоится из неё (корень репозитория).
  Пуш в master = мгновенный деплой, CI нет — **перед пушем прогоняй `npm test`**
  в `tests/`.
- **Изменения доводить до master без участия пользователя**: если прямой push в master
  недоступен, создать PR и сразу самостоятельно смерджить его
  (`gh pr merge --merge --delete-branch`; в средах без `gh` — через GitHub MCP/API).
- **В конце каждой сессии обновлять `DEVLOG.md`** (дата — что сделано).

## Известные ограничения

- API-ключ лежит в localStorage в открытом виде и отправляется из браузера —
  осознанный компромисс для статического хостинга без бэкенда.
- Приложение ориентировано на мобильный Chrome/Android (голосовой ввод);
  тестировать в первую очередь там.
- `MC_CORRECTIONS` использует lookahead-границы; замена всегда в нижнем регистре
  (как и раньше) — для ASR-текста это не мешает.
